# 上海迪士尼乐园 1:1 复刻与可玩设施

> 历史候选方案，已停止推进。用户后续选择 Linnanmäki；当前源码、地图资产和开发步骤见 `addons/linnanmaki/README.md`。

## 目标与状态

用户选择：真实上海迪士尼乐园完整复刻，同时让游乐设施可玩。
当前阶段：资料与范围定义；未生成地图、未实现新行为包、未部署。
技术基础：现有仓库为 Minecraft 基岩版 TypeScript 行为包。

## 比例与边界

- 比例：1 个完整方块边长对应现实 1 米；道路、建筑间距与总体布局保持这一比例。
- 亚米级细节采用台阶、半砖或自定义模型；方块表示存在离散误差，不能称为逐细节完全相同。
- 暂定范围：上海迪士尼乐园检票口以内的完整游客区域，包括入口、主题分区、道路、水体、景观、建筑外观、游客可进入的室内与游乐设施体验。
- 迪士尼小镇、酒店、停车场与其他度假区范围不属于上述默认边界；是否扩展需明确。
- 后台、地下管线及非公开设施缺少资料，不能声称已精确复刻。
- 园区版本须固定到一套有日期的资料；地图文件名不等同于已经核实的现场状态。

## 建模所需资料

1. 带坐标或可靠比例的底图，以及园区边界，用于统一道路、水体、建筑轮廓和控制点。
2. 建筑高度、立面和多个角度的参考，尤其是城堡与大型地标。
3. 游客可进入室内的参考、排队动线、上下客位置及乘坐路线。
4. 可选：已有 Minecraft 世界、结构文件或模型；先核验版本、比例和覆盖程度。

每个对象记录来源、资料日期、现实坐标、转换后的方块坐标、测量误差和完成状态。未经测量的尺寸标记为估算，不能通过 1:1 验收。

## 实施顺序与完成条件

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| 底图标定 | 统一原点、朝向、高程基准、边界及控制点 | 至少三个分散控制点验证坐标变换，误差记录可查 |
| 全园地形 | 水系、道路、桥梁、广场、建筑占地 | 对照已校准底图逐区检查，没有用缩放凑版面 |
| 建筑与景观 | 各区建筑、城堡、入口和景观 | 主要尺寸有来源，立面多视角对照，缺失资料明确列出 |
| 单项设施验证 | 一项完整的排队、上客、运行、下客体验 | 单人及多人实机验证，断线和重生能恢复 |
| 全设施扩展 | 按官方目录逐项制作 | 每个项目有完成记录，不以装饰入口代替可玩体验 |
| 全园验收 | 完整游览路线、设施目录、性能记录 | 全覆盖检查通过，测量误差与体验差异公开列明 |

入口—米奇大街—城堡轴线可作为首个细节验收区域；首个区域完成不代表全园完成。

## 可玩设施技术要求

- 统一状态：排队、上客、运行、下客、暂停与故障恢复。
- 过山车、漂流、旋转设施、室内剧情项目分别验证运动和交互，避免以同一种移动模板代替所有项目。
- 乘坐路线若无实测参考，明确标为体验近似，不声称真实轨道复刻。
- 基岩版自定义载具、模型、声音和动画可能需要配套资源包；先验证客户端兼容性。
- 导览应覆盖定位、区域导航、项目状态和安全退出。
- 分块生成和加载；记录生成耗时、帧率、脚本耗时和多人表现。性能阈值按实际服务器及客户端确定。
- 独立行为包与独立世界优先；开发时不复用现有小游戏的出生点或自动传送逻辑。
